# QA Criteria Template

**Customize this template to define quality assurance standards and rating criteria.**

---

## Overview

This template defines how content is evaluated during the QA phase. Customize criteria to match your quality standards.

**Purpose:** Ensure objective, consistent quality evaluation
**Usage:** Reference during QA phase (Phase 3) to achieve 5.0/5.0 rating

---

## Rating System

**5-point scale for each criterion:**

- **5** - Exceeds standards, exemplary quality
- **4** - Meets all standards, minor improvements possible
- **3** - Meets most standards, notable issues to address (BLOCK)
- **2** - Below standards, significant revision needed (BLOCK)
- **1** - Does not meet standards, major rewrite required (BLOCK)

**Overall Rating:** Average of all criteria ratings

**Minimum to proceed:** 5.0/5.0 (all criteria must be 5)

**If rating < 5.0:** Content MUST be revised and re-reviewed until 5.0 achieved

## Core QA Criteria

### 1. Brand Voice & Tone Consistency

**Evaluation questions:**
- [ ] Does the content match the brand voice template?
- [ ] Is tone appropriate for content type?
- [ ] Is perspective (first/second/third person) consistent?
- [ ] Are there any jarring tonal shifts?
- [ ] Does it sound authentically like the brand?

**Rating guidance:**
- **5** - Perfect brand voice, no inconsistencies
- **4** - Strong voice with 1-2 minor deviations
- **3** - Multiple voice inconsistencies (BLOCK)
- **2** - Voice doesn't match brand (BLOCK)
- **1** - Wrong voice entirely (BLOCK)

**Common issues:**
- Switching between formal and casual unexpectedly
- Inconsistent perspective shifts
- Generic voice that could be anyone
- Copying source voice instead of using brand voice

---

### 2. Content Quality & Originality

**Evaluation questions:**
- [ ] Does content provide original insights (not just rehashing sources)?
- [ ] Is information accurate and well-researched?
- [ ] Does content deliver real value to the reader?
- [ ] Is depth appropriate for the topic?
- [ ] Are practical applications or examples provided?

**Rating guidance:**
- **5** - Original insights, excellent depth, high value
- **4** - Good quality with minor gaps
- **3** - Mostly derivative or surface-level (BLOCK)
- **2** - Lacks substance or value (BLOCK)
- **1** - Inaccurate or misleading content (BLOCK)

**Common issues:**
- Simply summarizing sources without analysis
- Surface-level coverage without depth
- Missing practical applications
- No unique perspective or insight
- Outdated or inaccurate information

---

### 3. Technical Accuracy

**Evaluation questions:**
- [ ] Are all technical details correct?
- [ ] Do code examples work as written?
- [ ] Are commands and outputs accurate?
- [ ] Are version numbers and specifications current?
- [ ] Are technical concepts explained correctly?

**Rating guidance:**
- **5** - All technical content verified and correct
- **4** - Minor technical clarifications needed
- **3** - Notable technical errors present (BLOCK)
- **2** - Multiple technical inaccuracies (BLOCK)
- **1** - Fundamentally incorrect technical content (BLOCK)

**Common issues:**
- Code examples not tested
- Outdated API references
- Incorrect command syntax
- Wrong version numbers
- Misunderstood technical concepts

---

### 4. Source Integration & Verification

**Evaluation questions:**
- [ ] Are 10+ credible sources documented?
- [ ] Are all factual claims supported by sources?
- [ ] Are citations accurate and accessible?
- [ ] Is source attribution clear and correct?
- [ ] Are sources credible and current?

**Rating guidance:**
- **5** - 10+ sources, all claims verified, perfect attribution
- **4** - Good sourcing with 1-2 minor citation issues
- **3** - Missing sources or attribution (BLOCK)
- **2** - Insufficient sources (< 10) or major gaps (BLOCK)
- **1** - No source verification or false claims (BLOCK)

**Common issues:**
- Fewer than 10 sources
- Unsupported factual claims
- Broken or inaccessible source URLs
- Missing citations for data/statistics
- Using internal files as "sources"

---

### 5. Structure & Organization

**Evaluation questions:**
- [ ] Is content well-organized with logical flow?
- [ ] Are headers descriptive and hierarchical?
- [ ] Do sections connect smoothly with transitions?
- [ ] Is the opening engaging and the conclusion satisfying?
- [ ] Does structure match content type standards?

**Rating guidance:**
- **5** - Perfect structure, excellent flow, clear organization
- **4** - Good structure with minor improvements possible
- **3** - Notable structural issues affecting readability (BLOCK)
- **2** - Poor organization, hard to follow (BLOCK)
- **1** - No clear structure, chaotic (BLOCK)

**Common issues:**
- Sections out of logical order
- Missing key structural elements (intro, conclusion)
- Headers not descriptive enough
- Abrupt transitions or disconnected sections
- Doesn't follow content type template

---

### 6. Formatting & Readability

**Evaluation questions:**
- [ ] Is formatting consistent throughout?
- [ ] Are code blocks under 25 lines?
- [ ] Is there no horizontal scroll (80 char line limit)?
- [ ] Are lists and tables well-formatted?
- [ ] Is content scannable with appropriate white space?

**Rating guidance:**
- **5** - Perfect formatting, highly readable, scannable
- **4** - Good formatting with 1-2 minor issues
- **3** - Formatting issues affecting readability (BLOCK)
- **2** - Poor formatting, hard to scan (BLOCK)
- **1** - Broken formatting, unreadable (BLOCK)

**Common issues:**
- Code blocks cause horizontal scrolling
- Walls of text without breaks
- Inconsistent header formatting
- Tables too wide for viewport
- Missing or incorrect syntax highlighting

---

### 7. Accessibility & Clarity

**Evaluation questions:**
- [ ] Is content accessible to 90%+ of target audience?
- [ ] Are technical terms explained or defined?
- [ ] Is sentence structure clear and varied?
- [ ] Are concepts explained with examples?
- [ ] Is reading level appropriate for audience?

**Rating guidance:**
- **5** - Perfectly accessible, crystal clear explanations
- **4** - Clear with minor terminology improvements
- **3** - Accessibility issues, unclear sections (BLOCK)
- **2** - Confusing or overly complex (BLOCK)
- **1** - Incomprehensible to target audience (BLOCK)

**Common issues:**
- Unexplained jargon or acronyms
- Overly complex sentence structure
- Assumed knowledge gaps
- No examples for abstract concepts
- Reading level too high for audience

---

### 8. Completeness & Polish

**Evaluation questions:**
- [ ] Are all required sections present?
- [ ] Is there no placeholder content (TODO, TBD)?
- [ ] Are all links valid and accessible?
- [ ] Is the content thoroughly proofread?
- [ ] Are there any obvious gaps or omissions?

**Rating guidance:**
- **5** - Complete, polished, no placeholders or gaps
- **4** - Complete with 1-2 minor polish items
- **3** - Placeholders or notable gaps (BLOCK)
- **2** - Incomplete sections or multiple issues (BLOCK)
- **1** - Major sections missing or unfinished (BLOCK)

**Common issues:**
- TODO/TBD markers remaining
- Broken or missing links
- Incomplete sections
- Typos or grammatical errors
- Missing required elements

## Critical Blockers

**Content MUST be revised if any of these are present:**

### Mandatory Revisions (Auto-BLOCK)
- ❌ **QA rating < 5.0** - Must achieve perfect 5.0/5.0
- ❌ **Hardcoded counts** - Use "10+" not "10", dynamic not static
- ❌ **Time estimates** - Use "may take time" not "5 minutes"
- ❌ **Fewer than 10 sources** - Must have 10+ validated sources
- ❌ **Unsupported claims** - All facts must have source backing
- ❌ **Broken links** - All URLs must be accessible
- ❌ **Placeholder content** - No TODO, TBD, [PLACEHOLDER]
- ❌ **Code > 80 chars** - No horizontal scrolling
- ❌ **Technical errors** - All code/commands must be correct

**If ANY blocker is present:** Return to DRAFT phase, revise, re-run QA

## Claim Verification Process

**For each factual claim, verify:**

### Verification Steps
1. **Identify claim** - What specific fact is stated?
2. **Find source** - Which research source supports this?
3. **Verify accuracy** - Does source actually say this?
4. **Check citation** - Is source properly cited?

### Claim Types
**Factual claims requiring verification:**
- Statistics and data points
- Historical facts or dates
- Technical specifications
- Expert opinions or quotes
- Research findings
- Industry standards

**Claims NOT requiring sources:**
- Original analysis or insights
- Personal experiences
- Hypothetical examples
- General knowledge
- Obvious observations

### Verification Results
- ✅ **PASS** - Source supports claim, citation correct
- ⚠️ **CLARIFY** - Source partially supports, needs refinement
- ❌ **FAIL** - No source support or citation missing (BLOCK)

**If any claim fails:** Add proper source or remove unsupported claim

## QA Review Process

### Step 1: Initial Review
1. Read content completely
2. Note initial impressions
3. Identify obvious issues

### Step 2: Criteria Evaluation
1. Score each criterion (1-5)
2. Document specific feedback
3. Note examples of issues

### Step 3: Calculate Rating
1. Average all criterion scores
2. If < 5.0: Document required revisions
3. If 5.0: Approve for next phase

### Step 4: Document Results
Create `private/output/write/qa-review.json`:
```json
{
  "timestamp": "YYYY-MM-DDTHH:mm:ssZ",
  "overall_rating": 5.0,
  "criteria_ratings": {
    "brand_voice": 5,
    "content_quality": 5,
    "technical_accuracy": 5,
    "source_integration": 5,
    "structure": 5,
    "formatting": 5,
    "accessibility": 5,
    "completeness": 5
  },
  "feedback": {
    "strengths": ["...", "..."],
    "improvements": [],
    "blockers": []
  },
  "claim_verification": {
    "total_claims": 15,
    "verified_claims": 15,
    "failed_claims": 0
  },
  "revision_needed": false,
  "approved": true
}
```

### Step 5: Revision (if needed)
1. Review specific feedback
2. Address all blockers first
3. Make necessary revisions
4. Re-run QA review
5. Repeat until 5.0/5.0 achieved
